# Slice A: public tag page and finder actions

1. `src/app/t/[code]/page.tsx` plus a small client component for the finder buttons (e.g. `src/app/t/[code]/FinderActions.tsx`). Looks like the prototype's finder page: paper (light) surface regardless of theme, "REPORTED LOST" red banner when `item.lost`, "Currently with <lentTo>, borrowed not stolen" banner when `lentTo`, hero photo (`uploadUrl(item.photo)`) or a placeholder tile, "YOU FOUND" eyebrow + nickname (Unbounded 800, 34px) + "name · code", owner row ("Belongs to <owner.name>", `owner.contact` rendered as a `tel:` or `mailto:` link when it looks like a phone or email), the `finderNote`, up to 2 `publicStats` tiles, big "Message <owner name>" button that opens an inline form (name, contact, message) and "Share where I found it" (uses `navigator.geolocation`, optional place text, POSTs lat/lng), the reward line, owner links, `<ModelSection item={item} editable={false} />` only when `item.model3d && item.model3dPublic`, footer "TAG RD-001 · LOOT LOST & FOUND". Must render fine with JS disabled except for the two actions. Metadata: title "<nickname> · found it?" and `robots: { index: false }`. `notFound()` for unknown codes.
2. Scan logging: the page must not write on render (prefetch and bots would double count). `FinderActions` POSTs to `/api/t/[code]/scan` once on mount with a `sessionStorage` guard per code.
3. Route handlers: `src/app/api/t/[code]/scan/route.ts`, `.../message/route.ts`, `.../location/route.ts`. Validate with zod. Each: look up the item by code (404 if none), rate limit (key = `ip:<x-forwarded-for or 'local'>`, refuse with 429 when `recentEventsFromContact(key, 10) >= 20`; to make that work store the key in `who` for scan events, and for message/location store the finder's name in `who` but ALSO add a hidden scan-less check: simplest is a separate in-memory Map<ip, timestamps[]> in a module `src/lib/ratelimit.ts` that you create; use that instead of `recentEventsFromContact`). Honeypot field `website` must be empty. `addEvent` with type `scan` | `message` | `location`, `who` = finder's name or "Finder", `contact` stored on message events, `lat`/`lng` on location events, `text` = message or place. Return `{ ok: true }`. Never expose `serial`, `purchaseInfo`, `privateNotes`.

Do not create `Shell.tsx`. Create a stub `src/components/ModelSection.tsx` only if it is missing.
